# Canonical render scenes & distribution tests

Worked, version-controlled example of driving a **distributed render** through the Blender bridge
(the same path the addon uses) — and the canonical load-balancing tests that exercise it.

## Inputs

The canonical tests (`../Live/BridgeCanonicalDistributionTests.cs`) render two kinds of scene:

1. **Real, meaningful scenes** — [blender.org demo files](https://www.blender.org/download/demo-files)
   dropped into `@Data/` at the repo root (gitignored; tests self-skip when absent):
   - `@Data/cube_diorama/cube_diorama.blend` — a real 3D scene (Cycles).
   - `@Data/greasepencil-bike.blend` — an animated Grease Pencil scene.

2. **Artificial, self-contained scenes** — committed under `@Data/canonical/`, generated by the
   Python scripts here. Tiny (~0.1–0.5 MB) yet a real 120-frame animated effect:
   - `canonical_wave.blend` — rippling metallic surface + spinning emissive torus (Cycles & Eevee).
   - `canonical_greasepencil.blend` — a Grease Pencil Suzanne pinwheel.

   Fully procedural, animated with modifiers/keyframes only (no Python drivers — render nodes block
   those in untrusted files), so they stay git-committable.

## Regenerate the artificial scenes

Using any Blender 4.3+/5.x (e.g. the one bundled with the render controller under
`@Controllers/.../render.module/blender/<os>/blender`), from the repo root:

```
blender -b --python-exit-code 1 --python OutWit.Render.BlenderBridge.LocalTests/Canonical/gen_canonical_wave.py        -- @Data/canonical/canonical_wave.blend
blender -b --python-exit-code 1 --python OutWit.Render.BlenderBridge.LocalTests/Canonical/gen_canonical_greasepencil.py -- @Data/canonical/canonical_greasepencil.blend
```

## Run

`BridgeCanonicalDistributionTests` renders each case as a full-quality **1080p** video across the
live cluster (Cycles / Eevee / Grease Pencil), end-to-end through the bridge. `[Explicit]` and
env-gated on `OMNIBUSCLOUD_API_KEY`:

```
OMNIBUSCLOUD_API_KEY=... dotnet test --filter FullyQualifiedName~BridgeCanonicalDistribution
```

Each test logs its `JobId` right after submit so you can open **NODE ASSIGNMENTS** in the admin UI
and watch the per-node split while it renders. The output MP4 is written to
`@Output/canonical/<case>/` for inspection.
